# Evaluation — v0.22.0 simplified pre-production

Evaluate the system at three separate levels.

## 1. Clarification assessment and profile resolution

- Does every request produce a bound clarification assessment, using `status:"resolved"` with zero questions when the request is clear?
- Does a materially ambiguous request block only while actual questions await user input?
- Does the selected primary profile reflect the exact requested viewer outcome?
- Are supporting profiles genuinely necessary, and is explicit user intent preserved?

## 2. Creative reasoning and review checkpoints

Do not use one universal creative score. Audit whether one complete Script and one bounded correctness/fit self-check apply the active profile Success Definition without importing unrelated taste. There are no alternate Script candidates, dedicated Critic rounds, iterative model-review loops, or model-side final selection. The Script binds directly to the captured request, resolved clarification assessment, approved Video Brief, and frozen Production Profile; changing any frozen input must stale the review.

## 3. Canonical `video.json` → Remotion delivery

Storyboard approval is the single semantic canonical promotion boundary. Evaluate semantic fidelity, approved copy/narration, scene/story order, canonical frame-sum consistency, and whether Renderer Guidance helps without constraining Remotion local timing or overlap freedom. Evaluate materialized asset correctness separately after Enhance acquisition through the production registry.

Hard checks remain independent: duration, timeline coverage/no gaps/no blank tail, source/evidence freshness, audio binding, render success, manifest readiness, project revision state, and preflight.

The goal is not for every profile to produce the same style. The goal is for the core to stay stable while the request-specific definition of success changes explicitly through skill selection and reaches rendering through one approved Storyboard.
